Ce qui change dans js/billets.js (3 lignes, rien d'autre) :
  - estimerTailleOctets accepte un fichier sans dataUrl
  - les deux lecteurs (PDF et image) utilisent fichier.dataUrl || fichier.url
  Sans cette modification, un billet libéré (sans dataUrl) ne s'afficherait plus
  dans l'ancienne interface. Pour un billet non migré, le comportement est identique.

Dans le menu Plus (nouvelle interface activée) :
  - « Sauvegarde complète (fichier) » : télécharge un .json de toutes les fiches, corbeille comprise
  - « Billets : déplacer vers le stockage » : écran voyage par voyage
Sur l'écran Aujourd'hui : tuile « Prêt à partir ? ».

Ordre conseillé pour la migration :
  1. Sauvegarde complète, garder le fichier.
  2. Essayer sur UN seul voyage : Copier. Ouvrir ses billets et vérifier.
  3. Libérer la place seulement si tout s'ouvre. Retours : « Annuler la copie » (avant l'étape 3),
     « Restaurer depuis une sauvegarde » (après).

Points à savoir :
  - L'envoi utilise la fonction /upload-partage déjà présente dans le dépôt. Elle n'a pas pu être testée
    en réel ici : c'est la raison de l'essai sur un seul voyage.
  - Après déploiement, fermer et rouvrir l'application deux fois pour que la nouvelle version s'installe.
  - Les fonds de carte ne sont pas téléchargés pour le hors-ligne.
